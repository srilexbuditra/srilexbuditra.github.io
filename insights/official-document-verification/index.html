Official Document Verification dirancang untuk memberi jalur pemeriksaan publik melalui Document ID dan QR, kemudian mengambil status verifikasi melalui runtime berbasis API. Status, issued date, client, project, dan fingerprint ditampilkan dengan batas yang jelas agar QR maupun fingerprint tidak diposisikan melebihi bukti yang benar-benar tersedia.

Runtime Verifikasi Publik Bersifat API-Oriented

Runtime verification.js menggunakan fetch dan identifier SB_VERIFY_API untuk meminta data verifikasi. Source runtime saat ini tidak mereferensikan documents.json secara langsung, sehingga fallback static registry tidak diklaim sebagai perilaku frontend aktif.
